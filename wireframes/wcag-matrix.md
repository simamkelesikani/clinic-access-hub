# WCAG 2.1 AA Mapping Matrix

Domain: Community Healthcare Clinic - Accessible Healthcare Booking Portal (ticket MD-2026-0143).
This matrix covers 20 success criteria (14 rows) across the wireframes (`/wireframes`) and the React prototype (repository root).

| # | (a) Criterion ID and name | (b) Target interface component | (c) Technical implementation detail | (d) Verification strategy |
|---|---|---|---|---|
| 1 | **1.1.1 Non-text Content** (A) | Decorative icons, status indicators | No informative images are used. Decorative glyphs carry `aria-hidden="true"`. Status is always conveyed in text ("Urgent", "Routine"), never by icon alone. | axe rules `image-alt`, `svg-img-alt`. NVDA browse-mode read-through confirms no unexplained "graphic" announcements. |
| 2 | **1.3.1 Info and Relationships** (A) | Page structure, forms, data table | Landmarks (`header`, `nav`, `main`, `section`, `article`, `aside`, `footer`), one `h1` per page, ordered headings, `<fieldset>/<legend>` for groups, `<table>` with `<caption>` and `scope` attributes, every input paired with `<label for>`/`htmlFor`. | axe rules `landmark-one-main`, `region`, `heading-order`, `label`, `th-has-data-cells`. NVDA landmark (`D`) and heading (`H`) navigation. |
| 3 | **1.3.5 Identify Input Purpose** (AA) | Name, email and phone fields | `autocomplete="name"`, `"email"`, `"tel"` on the patient fields. | axe rule `autocomplete-valid`. Manual check that browser autofill populates fields. |
| 4 | **1.4.3 Contrast (Minimum)** (AA) | Body text, helper text, buttons, error text | All text pairs computed at 7.04:1 or higher (see comment table in `main.css`). Minimum ratio in the palette is 5.17:1 for primary-blue text on the surface colour. | Computed values documented in CSS. axe rule `color-contrast`. Manual spot check with a contrast analyser. |
| 5 | **1.4.4 Resize Text** (AA) and **1.4.10 Reflow** (AA) | Entire layout | Relative units (`rem`), fluid CSS grid with `auto-fit`, no fixed-height containers, single-column layout below 52rem. | Browser zoom to 200% and 400% at 1280px width: no clipped text, no horizontal scroll. |
| 6 | **1.4.11 Non-text Contrast** (AA) | Input borders, buttons, focus ring | Input borders `#4A5568` on white (7.53:1). Focus ring `#2B6CB0` on white (5.42:1) and `#FBD38D` on the dark header (8.56:1). | Computed values in CSS. Visual inspection of every control in focus. |
| 7 | **2.1.1 Keyboard** (A) and **2.1.2 No Keyboard Trap** (A) | All controls, accordion, filter chips, modal dialog | Native `<button>`, `<a>`, `<input>`, `<select>` used wherever possible. Modal is a `role="dialog"` with `aria-modal="true"`: focus moves in, Tab is contained only while the modal is open, and Escape plus a visible Close button always exit. | Component tests drive Tab and Enter/Space with `user-event`. Manual full-tab-sequence walk-through (logged in README). |
| 8 | **2.4.1 Bypass Blocks** (A) | Skip link and landmarks | First focusable element is "Skip to main content" targeting `#main`. | Manual: press Tab on page load, press Enter, confirm focus lands in `main`. Component test asserts the link and target exist. |
| 9 | **2.4.2 Page Titled** (A) | `<title>` of each wireframe page and each SPA view | Each wireframe has a unique, descriptive `<title>`. The SPA updates `document.title` on view change. | axe rule `document-title`. Test asserts title changes on navigation. |
| 10 | **2.4.3 Focus Order** (A) and **3.2.1 On Focus** (A) | Tab order, view changes, modal | DOM order matches visual order (no positive `tabindex`). On view change, focus moves to the new `h1` using `useRef` + `focus()` with `tabIndex={-1}`. On modal close, focus returns to the trigger. | Component tests assert `document.activeElement` after each transition. NVDA confirms the new heading is read. |
| 11 | **2.4.7 Focus Visible** (AA) | Every focusable element | Custom `:focus-visible` rule, `outline: 3px solid #2B6CB0; outline-offset: 2px`. No `outline: none` anywhere in the stylesheets. | Grep audit for `outline: none` / `outline:0`. Manual Tab walk-through with focus ring visible on all controls. |
| 12 | **3.3.1 Error Identification** (A), **3.3.2 Labels or Instructions** (A), **3.3.3 Error Suggestion** (AA), **3.3.4 Error Prevention** (AA) | Booking form | Visible labels and helper text (`aria-describedby`). Invalid fields get `aria-invalid="true"` and an error message linked via `aria-describedby`. Errors state how to fix ("Enter an email like name@example.com"). A review step lets the user check data before final confirmation. | Component tests for each validation rule. NVDA: submit an empty form and confirm the error summary and per-field errors are announced. |
| 13 | **4.1.2 Name, Role, Value** (A) | Accordion headers, filter chips, tabs | `aria-expanded` on accordion buttons, `aria-controls` linking button to panel, `aria-pressed` on toggle chips. State is derived from React state, so DOM and state cannot drift. | Component tests assert attribute values before and after click. axe rules `aria-valid-attr-value`, `button-name`. |
| 14 | **4.1.3 Status Messages** (AA) | Result count, validation outcome, booking confirmation | Persistent `role="status"` / `aria-live="polite"` region for result counts and confirmation. `aria-live="assertive"` (`role="alert"`) for the error summary on failed submit. Regions exist in the DOM before their text changes. | Tests assert region text after filter and submit. NVDA: confirm result count is announced after filtering. |
